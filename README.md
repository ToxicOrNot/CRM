# Локальная CRM

Локальная CRM-система для небольшой компании. На первом этапе система работает как постановщик задач: пользователи создаются администратором, авторизованные сотрудники создают задачи, назначают исполнителей, просматривают общие и личные задачи, открывают карточки и меняют статус.

## Стек

- Python 3.12+
- Django 5.2 LTS
- PostgreSQL
- Django Templates
- Bootstrap 5
- Docker Compose
- Django TestCase

## Требования

- Docker и Docker Compose
- Git
- Для локального запуска без Docker: Python 3.12+ и PostgreSQL или SQLite для быстрой проверки

## Быстрый запуск через Docker Compose

Создайте локальный файл окружения:

```powershell
copy .env.example .env
```

Запустите сервисы:

```powershell
docker compose up --build
```

Приложение будет доступно по адресу:

```text
http://localhost:8000/
```

Контейнер `web` перед запуском ожидает готовности PostgreSQL и применяет миграции автоматически.

## Миграции

Применить миграции вручную:

```powershell
docker compose exec web python manage.py migrate
```

Проверить, что модели соответствуют миграциям:

```powershell
docker compose exec web python manage.py makemigrations --check --dry-run
```

## Суперпользователь

Создать администратора:

```powershell
docker compose exec web python manage.py createsuperuser
```

Пользователи CRM создаются только через Django Admin:

```text
http://localhost:8000/admin/
```

## Тесты

Запуск тестов в Docker:

```powershell
docker compose exec web python manage.py test
```

Быстрый локальный запуск тестов на SQLite:

```powershell
$env:DJANGO_USE_SQLITE='1'; .\.venv\Scripts\python.exe manage.py test
```

## Структура проекта

```text
config/                 Настройки, root URL, WSGI/ASGI, главная страница
apps/accounts/          Пользовательская модель и admin пользователей
apps/tasks/             Модель задач, формы, views, URL, admin
templates/              Django Templates
static/                 Статические файлы проекта
media/                  Пользовательские файлы
tests/                  Сквозные тесты первого этапа
scripts/                Скрипты запуска контейнера и ожидания БД
manage.py               Django CLI
requirements.txt        Python-зависимости
Dockerfile              Образ Django-приложения
compose.yaml            PostgreSQL и Django-приложение
.env.example            Пример переменных окружения без реальных секретов
```

## Реализовано

- Собственная модель пользователя `accounts.User` на основе `AbstractUser`.
- Поля пользователя `position` и `department`.
- Модель `Task` со статусами и приоритетами через `TextChoices`.
- Автоматическое заполнение постановщика задачи текущим пользователем.
- Автоматическое управление `completed_at` при входе в статус `COMPLETED` и выходе из него.
- Проверка, что срок выполнения не раньше даты создания.
- Общий список задач.
- Раздел «Мои задачи».
- Создание, просмотр и редактирование задач.
- Прикрепление файлов к задачам.
- Скачивание файлов задачи из списка и карточки задачи.
- Права редактирования: постановщик, исполнитель или суперпользователь.
- Фильтры списка задач по статусу, исполнителю и просрочке.
- Защита всех страниц, кроме входа, от неавторизованных пользователей.
- Django Admin для пользователей и задач.
- Docker Compose с PostgreSQL healthcheck.
- Тесты ключевых сценариев первого этапа.

## Файлы задач в локальной сети

Файлы задач хранятся в локальной папке `media/` и доступны по URL вида:

```text
http://IP_СЕРВЕРА:8000/media/tasks/...
```

Для доступа с других ПК в локальной сети:

- запускайте приложение через Docker Compose, где Django слушает `0.0.0.0:8000`;
- откройте порт `8000` в firewall сервера;
- в `.env` оставьте `DJANGO_DEBUG=1` для локального dev-сервера;
- в `DJANGO_ALLOWED_HOSTS` укажите IP сервера или `*` для внутренней сети.

Для постоянной эксплуатации лучше отдавать `/media/` через Nginx или другой веб-сервер, а Django оставить только для приложения.

## Намеренно не реализовано

- Клиенты и клиентская база.
- Заказы.
- Отчёты.
- Уведомления.
- Kanban.
- REST API.
- SPA на React, Vue или аналогичных фреймворках.
- Публичная регистрация пользователей.
- Удаление задач через пользовательский интерфейс.
