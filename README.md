# Локальная CRM

Локальная CRM-система для небольшой компании. Сейчас система закрывает постановку задач, учет заказов и нормализованную клиентскую базу. Заказы могут быть связаны с клиентами, но поле `Order.contacts` сохраняется как контактный снимок на момент оформления заказа.

## Стек

- Python 3.12+
- Django 5.2 LTS
- PostgreSQL
- Django Templates
- Bootstrap 5
- Docker Compose
- Django TestCase
- phonenumbers для нормализации телефонов

## Требования

- Docker и Docker Compose
- Git
- Для локального запуска без Docker: Python 3.12+ и PostgreSQL или SQLite для быстрой проверки

## Быстрый запуск через Docker Compose

Создайте локальный файл окружения:

```powershell
copy .env.example .env
```

Запустите сервисы:

```powershell
docker compose up --build
```

Приложение будет доступно по адресу:

```text
http://localhost:8000/
```

Контейнер `web` перед запуском ожидает готовности PostgreSQL и применяет миграции автоматически.

## Миграции

Применить миграции вручную:

```powershell
docker compose exec web python manage.py migrate
```

Проверить, что модели соответствуют миграциям:

```powershell
docker compose exec web python manage.py makemigrations --check --dry-run
```

## Суперпользователь

Создать администратора:

```powershell
docker compose exec web python manage.py createsuperuser
```

Пользователи CRM создаются через Django Admin:

```text
http://localhost:8000/admin/
```

## Тесты

Запуск тестов в Docker:

```powershell
docker compose exec web python manage.py test
```

Быстрый локальный запуск тестов на SQLite:

```powershell
$env:DJANGO_USE_SQLITE='1'; .\.venv\Scripts\python.exe manage.py test
```

## Модуль задач

Реализовано:

- собственная модель пользователя `accounts.User` на основе `AbstractUser`;
- поля пользователя `position` и `department`;
- модель `Task` со статусами и приоритетами через `TextChoices`;
- автоматическое заполнение постановщика задачи текущим пользователем;
- автоматическое управление `completed_at` и архивированием при отметке «Выполнена»;
- общий список задач, «Мои задачи» и архив задач;
- создание, просмотр и редактирование задач;
- разворачивание карточки задачи прямо в списке;
- прикрепление файлов к задачам и скачивание всех файлов одним ZIP-архивом;
- права редактирования задачи: постановщик, исполнитель или суперпользователь;
- фильтры и сортировка списка задач;
- связь задачи с заказом через необязательное поле `Task.order`.

## Модуль заказов

Модель `Order` содержит:

- `order_date` — дата заказа;
- `delivery_date` — дата выдачи, автоматически заполняется при переводе заказа в статус `DELIVERED`;
- `status` — статус заказа;
- `order_number` — номер заказа, допускает пустое значение и повторы из старой Excel-таблицы;
- `work_information` — информация о работе;
- `contacts` — контактные данные клиента в свободной форме;
- `original_contacts` — исходная контактная строка заказа, если `contacts` был автоматически дополнен данными клиента;
- `client` — необязательная ссылка на клиента;
- `total_amount` — сумма к оплате;
- `advance_amount` — аванс;
- `additional_payment` — доплата;
- `comment` — комментарий;
- `created_by`, `created_at`, `updated_at`;
- `archived` — архивный признак.

Статусы заказа:

- `ACCEPTED` — Новый;
- `WAITING_RESPONSE` — Ожидаем ответ/предоплату;
- `IN_PROGRESS` — В работе;
- `READY` — Позвонили о готовности;
- `DELIVERED` — Заказ отдан;
- `CANCELLED` — Отменен.

Финансовый расчет:

```text
Остаток = Сумма к оплате - Аванс - Доплата
```

Остаток не хранится в базе данных, а вычисляется свойством `Order.balance`. Денежные поля используют `DecimalField`, отрицательные значения запрещены, аванс и доплата вместе не могут превышать сумму заказа.

В интерфейсе заказов реализовано:

- список активных заказов;
- бесконечная подгрузка заказов при прокрутке вместо ручного переключения страниц;
- создание и редактирование заказов;
- разворачивание заказа прямо в списке кликом по строке;
- быстрое изменение статуса, суммы, аванса и доплаты из раскрытой строки заказа;
- карточка заказа с блоками информации, финансов, комментария, связанных задач и служебных данных;
- поиск по номеру заказа, информации о работе, контактам и комментарию;
- фильтры по статусу, датам, просрочке, оплате и остатку;
- сортировка по дате заказа, дате выдачи, сумме и остатку;
- архив заказов без физического удаления;
- восстановление заказа из архива;
- кнопка «Создать задачу для заказа» с предзаполненной связью с заказом.
- выбор клиента в заказе;
- автозаполнение `contacts` контактным снимком клиента;
- отображение ссылки на клиента, снимка контактов заказа и актуальных контактов клиента в карточке заказа.

Импорт старой Excel-таблицы:

```powershell
docker compose exec web python manage.py import_orders_xlsx "заказы 2025 — копия.xlsx" --dry-run
docker compose exec web python manage.py import_orders_xlsx "заказы 2025 — копия.xlsx" --created-by admin
docker compose exec web python manage.py import_orders_xlsx "заказы 2025 — копия.xlsx" --created-by admin --last 10
```

`--dry-run` показывает сводку без записи в базу. При импорте:

- статус берется из текстовой колонки, а если она пустая — из цвета строки Excel;
- Excel-статус «Заказ создан» импортируется как CRM-статус «В работе»;
- поле «где печатаем» и дополнительные пометки из правых колонок сохраняются в комментарий заказа;
- некорректные денежные значения не останавливают импорт, а заносятся в комментарий как предупреждения;
- если в Excel аванс и доплата больше суммы заказа, сумма к оплате поднимается до суммы платежей, чтобы в CRM не появлялся отрицательный остаток;
- дата выдачи переносится только для заказов со статусом «Заказ отдан» и не переносится, если она раньше даты заказа;
- пустые даты заказа наследуются от предыдущей заполненной строки таблицы.

## Права доступа к заказам

Модуль заказов использует стандартные Django permissions:

- `orders.view_order` — просмотр списка и карточки;
- `orders.add_order` — создание;
- `orders.change_order` — редактирование, архивирование и восстановление;
- суперпользователь имеет полный доступ.

Права назначаются через Django Admin. Отдельная ролевая модель для заказов пока не создавалась.

## Модуль клиентов

Клиентская база реализована в приложении `apps.clients`.

Список клиентов и архив клиентов используют бесконечную подгрузку при прокрутке вместо ручного переключения страниц.

Модель `Client` содержит:

- `display_name` — имя клиента, может быть пустым;
- `preferred_channel` — предпочтительный канал связи из общего `ContactType`;
- `comment` — комментарий по клиенту;
- `source_text` — исходная строка, из которой клиент был создан или разобран;
- `created_by`, `created_at`, `updated_at`;
- `archived` — архивный признак.

Модель `ClientContact` содержит:

- `client` — связь с клиентом;
- `contact_type` — тип контакта из общего `ContactType`;
- `raw_value` — исходное значение без изменения;
- `normalized_value` — нормализованное значение для поиска и сравнения;
- `label`, `comment`;
- `is_primary` — основной контакт.

Типы контактов:

- `PHONE` — Телефон;
- `WHATSAPP` — WhatsApp;
- `TELEGRAM` — Telegram;
- `MAX` — MAX;
- `EMAIL` — Email;
- `OTHER` — Другое.

Ограничения:

- у клиента может быть только один основной контакт;
- внутри одного клиента запрещены два одинаковых контакта с одинаковыми `contact_type` и `normalized_value`;
- одинаковый контакт у разных клиентов разрешен;
- клиенты не объединяются автоматически.

### Нормализация контактов

`raw_value` всегда хранит исходное значение. `normalized_value` заполняется сервером и не редактируется в обычной форме.

Телефоны нормализуются через `phonenumbers`:

- `8 926 070 43-18` → `+79260704318`;
- `7 991 288-82-81` → `+79912888281`;
- `+7 977 373-09-48` → `+79773730948`;
- `8916985 25-70` → `+79169852570`;
- `+37455212261` → `+37455212261`.

Если номер начинается с `+`, код страны сохраняется и номер разбирается без региона `RU`. Поэтому международный номер не подгоняется под `+7`.

Telegram:

- `@Erina197`, `t.me/Erina197`, `https://t.me/Erina197` нормализуются в `erina197`;
- при отображении username показывается с `@`;
- номер с маркером `TG` или `Telegram` создается как Telegram-контакт с телефонной нормализацией.

WhatsApp:

- маркеры `WA`, `WhatsApp`, `вотсап`, `ватсап`, `вацап` распознаются как WhatsApp;
- WhatsApp всегда нормализуется как телефон.

MAX:

- отдельные слова `макс`, `мах`, `max` распознаются как канал MAX;
- регистр не важен;
- маркер должен быть отдельным токеном;
- слова `Максим`, `максим`, `Максимов`, `максимальный`, `maximum`, `xmax` не считаются маркером MAX и не повреждаются.

Пример `Индира мах`:

- `display_name`: `Индира`;
- `preferred_channel`: `MAX`;
- контакт не создается, потому что нет номера или username;
- `source_text` сохраняет исходную строку.

### Предварительный разбор

Страница «Разобрать строку» не создает клиента сразу. Она показывает предполагаемые поля, контакты, нормализованные значения, предупреждения, уверенность и флаг ручного подтверждения. Клиент сохраняется только после подтверждения пользователем, а значения повторно валидируются на сервере.

### Дубли

Сервис поиска потенциальных дублей определяет:

- сильное совпадение: одинаковый тип и `normalized_value`;
- среднее совпадение: одинаковый телефон между `PHONE`, `WHATSAPP`, `TELEGRAM` и `MAX`;
- слабое совпадение: одинаковое имя.

Дубли только показываются предупреждением. Автоматическое объединение клиентов не реализовано.

### Связь клиентов и заказов

`Order.client` — необязательная ссылка на клиента. Старые заказы остаются с `client = NULL`.

`Order.contacts` не удаляется и не синхронизируется с клиентом. Это снимок контактов на момент оформления заказа:

- изменение `Order.contacts` не меняет `ClientContact`;
- изменение `ClientContact` не переписывает старые заказы;
- архивный клиент не предлагается в форме нового заказа, но старые заказы такого клиента продолжают открываться.

Из карточки клиента можно создать заказ. В этом случае клиент подставляется автоматически, а `Order.contacts` получает снимок основного или предпочтительного контакта.

Из карточки заказа можно нажать «Создать/определить клиента». Система разберет `Order.contacts`:

- если найденный нормализованный телефон или Telegram/MAX username указывает на одного существующего клиента, заказ будет привязан к нему;
- если совпадений нет, будет создан новый клиент и контакты;
- если найдено несколько возможных клиентов, автоматического выбора не будет;
- существующие контакты клиента не перезаписываются, недостающие контакты добавляются;
- пустые поля клиента могут быть дополнены данными из заказа.

При создании нового заказа система автоматически применяет то же правило к полю `Order.contacts`: клиент создаётся или привязывается только если в строке есть имя и конкретный контакт: телефон, email, Telegram/MAX username или ссылка. Если найден уже существующий клиент и в его карточке больше данных, `Order.contacts` заменяется полным снимком из базы: имя клиента и значения контактов без подписей типа `Телефон` или `Telegram`. Исходная строка, введённая в заказе, сохраняется в `Order.original_contacts` и показывается в карточке заказа. Если в контактах указано только имя без контакта или только телефон без имени, клиент автоматически не создаётся и не привязывается.

Массовая обработка заказов:

```powershell
docker compose exec web python manage.py resolve_order_clients --dry-run
docker compose exec web python manage.py resolve_order_clients --created-by admin
```

Команда обрабатывает только заказы, где в `contacts` одновременно найдены имя и конкретный телефон, email, Telegram/MAX username или ссылка. Строки вида «Имя + соцсеть» без номера или username, а также строки только с телефоном без имени пропускаются. При совпадении нормализованного контакта с одним существующим клиентом заказ привязывается к нему, а недостающие контакты добавляются. Если совпадений нет, создается новый клиент. Если совпадений несколько, заказ пропускается как неоднозначный.

### Анализ старых контактов заказов

Команда анализа:

```powershell
docker compose exec web python manage.py analyze_order_contacts --csv order_contacts_report.csv
```

По умолчанию команда только анализирует `Order.contacts`, не меняя базу.

Безопасное применение:

```powershell
docker compose exec web python manage.py analyze_order_contacts --csv order_contacts_report.csv --apply-safe
```

`--apply-safe`:

- не создает новых клиентов;
- не объединяет клиентов;
- не меняет `Order.contacts`;
- заполняет только `Order.client`;
- работает только при однозначном совпадении с одним существующим клиентом.

## Права доступа к клиентам

Модуль клиентов использует стандартные Django permissions:

- `clients.view_client` — просмотр списка и карточки;
- `clients.add_client` — создание и подтверждение разбора строки;
- `clients.change_client` — редактирование, архивирование и восстановление;
- `clients.delete_client` технически существует, но физическое удаление через пользовательский интерфейс не реализовано.

Права назначаются через Django Admin.

## Файлы задач и заказов в локальной сети

Файлы задач и заказов хранятся в локальной папке `media/` и доступны по URL вида:

```text
http://IP_СЕРВЕРА:8000/media/tasks/...
http://IP_СЕРВЕРА:8000/media/orders/...
```

Для доступа с других ПК в локальной сети:

- запускайте приложение через Docker Compose, где Django слушает `0.0.0.0:8000`;
- откройте порт `8000` в firewall сервера;
- в `.env` оставьте `DJANGO_DEBUG=1` для локального dev-сервера;
- в `DJANGO_ALLOWED_HOSTS` укажите IP сервера или `*` для внутренней сети.

Для постоянной эксплуатации лучше отдавать `/media/` через Nginx или другой веб-сервер, а Django оставить только для приложения.

## Backup заказов и клиентов

Резервные копии заказов, клиентов и контактов клиентов сохраняются в папку `backups/`.

Команда ручного запуска:

```powershell
docker compose exec web python manage.py backup_crm_data
```

По умолчанию команда создаёт два файла:

- `crm_backup_YYYYMMDD_HHMMSS.json` — машинный снимок данных;
- `crm_backup_YYYYMMDD_HHMMSS.xlsx` — Excel-книга с листами `Orders`, `Clients`, `ClientContacts`, `Metadata`.

Можно выбрать формат:

```powershell
docker compose exec web python manage.py backup_crm_data --format json
docker compose exec web python manage.py backup_crm_data --format xlsx
docker compose exec web python manage.py backup_crm_data --format both
```

В backup входят:

- все заказы, включая архивные;
- все клиенты, включая архивных;
- все контакты клиентов;
- финансовые поля заказа и рассчитанный остаток;
- связь заказа с клиентом;
- служебные даты создания и изменения.

Файлы задач и заказов из `media/` в этот backup не входят.

Для ежедневного запуска в 21:58 через Windows Task Scheduler выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install_daily_backup_task.ps1
```

Или запустите двойным кликом:

```text
scripts\install_daily_backup_task.bat
```

Плановая задача запускает `scripts\run_daily_backup.ps1`. Скрипт при необходимости запускает Docker Desktop, поднимает контейнеры через `docker compose up -d` и выполняет команду backup внутри контейнера `web`.

Лог планового backup:

```text
backups\scheduled_backup.log
```

## Намеренно не реализовано

- платежные транзакции, касса и бухгалтерский учет;
- интеграция с банком;
- автоматическое формирование документов;
- SMS и Telegram-уведомления;
- история всех изменений;
- отчеты по прибыли;
- складской учет;
- сложные производственные маршруты;
- автоматическое создание клиентов из всех заказов;
- автоматическое слияние клиентов;
- fuzzy-объединение по имени;
- интеграции с Telegram, WhatsApp, MAX и внешними API;
- массовые рассылки;
- Kanban;
- REST API;
- SPA на React, Vue или аналогичных фреймворках;
- публичная регистрация пользователей;
- физическое удаление задач и заказов через пользовательский интерфейс.
